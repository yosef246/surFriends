# כניסה אנונימית (ללא Google)

## מה השתנה
- אין יותר מסך התחברות ואין Google. כל הדפים ציבוריים (ה-middleware רק מרענן עוגיית סשן, בלי הפניות).
- בפתיחת האפליקציה `SessionBootstrap` (צד לקוח) בודק סשן, ואם אין, קורא ל-`supabase.auth.signInAnonymously()` ואז `router.refresh()`. המשתמש לא רואה את זה; RLS, הגבלות קצב, מועדפים, פוש ומחיקת דיווחים עובדים כמו קודם על `auth.uid()`.
- מסך הכניסה הישן הפך ל-Splash של כ-2 שניות (פעם אחת לכל סשן דפדפן, וגם ב-PWA). הוא נשאר לפחות 2 שניות ועד שהסשן מוכן, ולכל היותר 4 שניות.
- אחרי ה-Splash, אם לפרופיל `name_chosen = false`, מוצג מסך "איך קוראים לך בים?": שם (2-40 תווים, חובה, בלי דילוג) ורמת גלישה אופציונלית. השם מופיע בברכה בפיד ("בוקר טוב <שם>").
- `/login` ו-`/callback` מפנים (301) ל-`/`. הכפתור, ה-callback, `safe-next` ו-`in-app-browser` נמחקו; הכפתור "התנתקות" הוסר מההגדרות.
- `robots.txt`: מותר `/` ו-`/beach/`; חסום `/api`, `/settings`, `/profile`, `/new`.

## מיגרציה
להריץ ב-SQL Editor את `supabase/migrations/20261029070000_anonymous_users.sql` (בטוחה להרצה חוזרת):
- עמודה `profiles.name_chosen` (ברירת מחדל false; משתמשי Google הקיימים מסומנים true פעם אחת).
- `handle_new_user`: משתמש אנונימי (בלי אימייל ובלי שם) מקבל `גולש/ת`.
- הרשאת UPDATE על `name_chosen` למשתמש מחובר (דגל UX בלבד, RLS מגביל לשורה שלו). `updateProfile` מעלה אותו ל-true בכל שמירת שם.

## צעדים ב-Supabase Dashboard
1. Authentication, Sign In / Providers: להפעיל **Allow anonymous sign-ins**.
2. להריץ את המיגרציה.
3. אחרי שבדקתם שהכניסה עובדת: לכבות את ספק Google (ואופציונלי למחוק את ה-OAuth client ב-Google Cloud).
4. אופציונלי: להפעיל CAPTCHA, ולכוונן את מגבלות ה-anonymous sign-ins ב-Authentication, Rate Limits (ברירת המחדל מוגבלת לפי IP).

## פשרות
- הזהות קשורה לדפדפן/מכשיר: ניקוי נתוני הדפדפן יוצר פרופיל חדש, ודיווחים ישנים נשארים תחת הפרופיל הקודם.
- אין הגנה מפני יצירת חשבונות רבים אלא מגבלות הקצב של Supabase (ו-CAPTCHA אם הופעל).
- אם כניסה אנונימית כבויה או חסומה, מוצגת הודעה "לא הצלחנו להתחבר לשרת. נסו לרענן" והדפים הציבוריים ממשיכים לעבוד.
