# מצב לילה: הים סגור משקיעה עד זריחה

## הכלל
בין השקיעה לזריחה (לפי יום קלנדרי בישראל, `Asia/Jerusalem`) אי אפשר לפרסם דיווח חדש, להגיב, או ללחוץ "אני בא" / "בדרך". קריאה בלבד. מחיקה של דיווח/תגובה עצמיים נשארת מותרת.
לילה = `עכשיו < זריחת היום` או `עכשיו >= שקיעת היום`.

## החישוב
משוואת הזריחה של NOAA (Solar Calculator), זנית 90.833 מעלות, נקודת ייחוס תל אביב (32.08N, 34.78E); חוף ישראל כולו בטווח של כמה דקות. אין תלות חיצונית, והשעון המקומי/DST מגיע מ-`Intl` עם `Asia/Jerusalem` (בלי היסטים קבועים).
- TypeScript: `lib/daylight.ts` (`getDaylightState(now)` מחזיר `{ isNight, closesAt, opensAt, minutesUntilOpen }`).
- SQL: `public.is_night_israel(ts)` במיגרציה, אותה נוסחה.
- בדיקות: `tests/daylight.test.ts`, מול `api.sunrise-sunset.org` (אותם ערכים בטווח שניות; הסף בבדיקה 3 דקות), כולל מעברי שעון קיץ.
- ב-2026-06-21: זריחה 05:35 ושקיעה 19:50. ב-2026-12-21: זריחה 06:37 ושקיעה 16:40.

## שכבות האכיפה
1. UI (נוחות בלבד): `DaylightProvider`/`useDaylight()` (state מהשרת, ועדכון בלקוח כל 60 שניות). מסך לילה מלא (`NightScreen`), כפתור "דיווח" פותח גיליון נחמד, `/new` מציג כרטיס סגור, כפתורי "אני בא"/"בדרך" ותיבת התגובה מושבתים עם הערה "התגובות ייפתחו בזריחה (HH:mm)".
2. Server actions: `createReport`, `replyToReport`, `toggleReaction` מחזירים `הים סגור בלילה 🌙 נפתח שוב ב-HH:mm` לפני כל כתיבה. `deleteReport`/`deleteReply` לא מושפעים.
3. מסד הנתונים: הטריגרים `guard_report_insert`/`guard_reply_insert` זורקים `night_closed` כש-`is_night_israel()` ו-`auth.uid() IS NOT NULL` (ה-SQL Editor ו-service role פטורים, כמו מגבלות הקצב). ההעלאות ל-Storage לא נחסמות: בלי דיווח אין מה לצרף, וקבצים יתומים מנוקים ב-TTL.

## "הצצה"
כפתור "להציץ בדיווחים מהיום" סוגר את המסך לסשן (`sessionStorage`, מפתח `sf_night_peek`, תקף עד הזריחה הבאה). האפליקציה נשארת לקריאה בלבד. כשהזריחה עוברת והאפליקציה פתוחה: המסך נעלם, הפעולות נפתחות, ומופיע "בוקר טוב! הים נפתח 🌅".

## שינוי מרווח הביטחון
`SAFETY_BUFFER_MIN` ב-`lib/daylight.ts` (ברירת מחדל 0; למשל 30 = סגירה חצי שעה לפני השקיעה). יש לעדכן במקביל את `buffer_min` בפונקציית ה-SQL ולהריץ את המיגרציה מחדש. הזריחה לא מושפעת.

## מיגרציה להרצה
`supabase/migrations/20261103000000_night_lockout.sql` (ב-SQL Editor של פרויקט Supabase; בטוחה להרצה חוזרת).
**חשוב:** לפני ההרצה פונקציות השרת כבר חוסמות, אבל ה-REST ישיר לא. ההרצה לא נבדקה מול Postgres מקומי (Docker לא רץ), כדאי לבדוק אחריה: `select public.is_night_israel();` ובדיקת סיבוב מול `select public.is_night_israel('2026-06-21 17:00:00+00')` (אמור להחזיר true, 20:00 בישראל).
