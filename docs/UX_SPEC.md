# surFriends — UX Spec (יום 3, חצי UX)

> גרסה 1.0. מסמך זה מגדיר מבנה, זרימות, רכיבים ומצבים. **לא** מגדיר צבעים, פונטים או ריווח. את אלה ה-visual-designer קובע לפי טוקנים מ-spec §9 (`--sea-deep`, `--sea-wave`, `--sand`, `--foam`, `--sunset`, `--kelp`, `--shadow`, `--mist`).
> מקורות מחייבים: `surFriends-spec.md` §8 (routes + שמות רכיבים), `supabase/migrations/*.sql`, `lib/database.types.ts`. מסך מציג רק שדות שקיימים בסכמה.

## 0. עקרונות כלליים

- **Mobile-first, RTL.** כל ה-wireframes קריאים מימין לשמאל: הפריט הראשון בימין. ה-FAB "+" נמצא **שמאל-למטה**, מעל ה-BottomNav.
- **גישה:** כל route ב-`(app)` דורש התחברות. משתמש לא מחובר מועבר ל-`/login?next=<path>`. אחרי התחברות חוזרים ל-`next`.
- **מגבלות נתונים שמשפיעות על ה-UX (חשוב):**
  - `reports.text` חובה (1–500). אי אפשר לפרסם בלי טקסט. `image_url`, `wave_rating`, `wave_height_estimate` אופציונליים.
  - `replies`: חייב טקסט (עד 200) **או** `quick_reaction` (`coming` / `on_the_way`), או שניהם.
  - `user_favorites` נקרא רק על ידי הבעלים (RLS). לכן ב-`/profile/[id]` של משתמש אחר **לא מציגים חופים מועדפים**.
  - אין UPDATE על reports/replies. אין עריכת דיווח, רק מחיקה של שלי.
  - Storage: bucket `report-images`, עד 5MB, jpeg/png/webp/gif/heic/heif, נתיב `{user_id}/...`. אין bucket לאווטארים, לכן האווטאר נשאר זה של Google (אין העלאת אווטאר).
  - `created_at` הוא nullable בטיפוסים. null מוצג כ"עכשיו".
  - אין unique על replies. מניעת "אני בא" כפול נעשית בצד לקוח (ראו §3.2).
- **טוקנים בלבד.** כשכתוב "מודגש" או "צבע התראה" הכוונה לטוקן שה-visual-designer יבחר. אף מצב אינו מועבר בצבע בלבד.
- **Relative time (כל המסכים):** רכיב `RelativeTime`. פורמט: פחות מדקה "עכשיו", "לפני 5 דקות", "לפני שעתיים", "אתמול 18:20", ואז "28.10". מתעדכן כל 60 שניות. הזמן המלא ("יום ג׳ 28.10, 07:42") מופיע ב-`title` (hover), ב-`aria-label`, ובלחיצה ארוכה (500ms) שמציגה tooltip קטן ל-3 שניות. בנוסף, ב-ReportCard המורחב (דף חוף) לחיצה קצרה על הזמן מציגה אותו, כי לחיצה ארוכה לא ניתנת לגילוי.

## 2. המסכים

### 2.1 Login — `/login`

**מטרה:** כניסה בלחיצה אחת עם Google. אין טופס.

```
┌─────────────────────────────┐
│                             │
│                             │
│          [ לוגו ]           │
│         surFriends          │
│  קהילת הגולשים של ישראל     │
│                             │
│  ┌───────────────────────┐  │
│  │ G  המשך עם Google     │  │
│  └───────────────────────┘  │
│                             │
│  בהמשך אתם מסכימים לתנאים   │
│        (טקסט קטן)           │
└─────────────────────────────┘
```

**היררכיית רכיבים:** `LoginPage` > Logo, Tagline, `Button` (Google, full-width), `InlineError` (מותנה).
רכיבי shadcn: Button. אין TopBar ואין BottomNav.

**נתונים:** אין. אחרי callback הטריגר `handle_new_user` יוצר `profiles` (`display_name` מ-Google, `avatar_url` מ-Google). ה-UI לא מבקש שם.

**מצבים:**
- Default: כפתור פעיל.
- Loading: אחרי לחיצה הכפתור disabled עם spinner וטקסט "מתחברים...". נשאר עד redirect.
- Error: `/login?error=...` מציג `InlineError` מעל הכפתור: "משהו השתבש בהתחברות. נסו שוב." והכפתור חוזר לפעיל. ביטול במסך Google חוזר עם אותו מסר.
- Offline: הכפתור disabled, שורה: "אין חיבור לאינטרנט".
- Already logged in: redirect מיידי ל-`/`.
- Edge: דפדפן פנימי (WhatsApp/Instagram) חוסם Google OAuth. זיהוי user-agent ומסר: "פתחו את הקישור בדפדפן (Chrome/Safari) כדי להתחבר" + כפתור "העתק קישור".

**אינטראקציות:** לחיצה > `signInWithOAuth('google')` > callback > `/` (או `next`). אין micro-interaction מעבר ל-spinner.

**Microcopy:** כותרת "surFriends", תת-כותרת "קהילת הגולשים של ישראל", כפתור "המשך עם Google".

### 2.2 Feed — `/`

**מטרה:** לראות מה קורה עכשיו בחופים, להגיב בלחיצה, ולדווח.

```
┌─────────────────────────────┐
│ surFriends        [⚲ סינון] │  <- TopBar (לוגו ימין, סינון שמאל)
│ [חוף הילטון ✕] (chip פעיל)  │
├─────────────────────────────┤
│   ( 3 דיווחים חדשים ↑ )     │  <- NewReportsPill (מרחף, מופיע לפי צורך)
│ ┌─────────────────────────┐ │
│ │(אב) דני כהן             │ │  ReportCard
│ │ חוף הילטון · לפני 5 דק׳ │ │
│ │ גלים ●●●●○ 4/5 · טובים  │ │
│ │ גובה: כתף               │ │
│ │ "נקי, אין אף אחד בפנים" │ │
│ │ ┌─────────────────────┐ │ │
│ │ │       [ תמונה ]     │ │ │
│ │ └─────────────────────┘ │ │
│ │ [אני בא] [בדרך] [תגובה] │ │  QuickReactionBar
│ │ 3 תגובות · 2 "אני בא" ▾ │ │  ReplyThread (מכווץ)
│ └─────────────────────────┘ │
│ ┌─────────────────────────┐ │
│ │  ...                    │ │
│ └─────────────────────────┘ │
│                             │
│ (+)                         │  <- FAB, שמאל-למטה
├─────────────────────────────┤
│ [הגדרות] [פרופיל] [פיד]     │  <- BottomNav (פיד בימין)
└─────────────────────────────┘
```

**היררכיית רכיבים:**
`FeedPage` > `TopBar` (Logo, `FilterButton`, chip סינון פעיל) · `FilterSheet` (חדש) > `BeachPicker` (מצב סינון) · `NewReportsPill` (חדש) · `ReportList` > `ReportCard` > [`Avatar`, `RelativeTime`, `WaveRating` (חדש, תצוגה), `QuickReactionBar`, `ReplyThread`] · `StripForecast` (ראו להלן, משתמש ב-`ForecastSummary`) · `FAB` (חדש) · `BottomNav` · `EmptyState` (חדש) · `OfflineBanner` (חדש).

**מיפוי נתונים ל-ReportCard:**

| אלמנט | מקור |
|-------|------|
| אווטאר + שם (קישור ל-`/profile/[user_id]`) | `profiles.avatar_url`, `profiles.display_name` (join דרך `reports.user_id`). אם אין avatar: ראשי תיבות |
| שם חוף (קישור ל-`/beach/[beach_id]`) | `beaches.name_he` |
| זמן | `reports.created_at` > `RelativeTime` |
| דירוג גלים | `reports.wave_rating` (1–5) > `WaveRating`. אם null: לא מוצג |
| גובה משוער | `reports.wave_height_estimate` (טקסט חופשי). אם null: לא מוצג |
| טקסט | `reports.text` (חיתוך ל-4 שורות + "עוד") |
| תמונה | `reports.image_url`, יחס קבוע, lazy, לחיצה פותחת תצוגה מוגדלת (overlay פשוט עם סגירה) |
| ספירת תגובות | count של `replies` לפי `report_id` |
| ספירת "אני בא" / "בדרך" | count של `replies.quick_reaction` = `coming` / `on_the_way` |
| תפריט ⋯ (רק לבעלים) | `reports.user_id` = משתמש נוכחי > "מחק דיווח" |

**`WaveRating`:** תמיד מוצג כשלושה רמזים יחד: מספר ("4/5"), 5 סימנים מלאים/ריקים (צורה, לא צבע), ותווית מילולית. תוויות: 1 "שטוח", 2 "חלש", 3 "סביר", 4 "טוב", 5 "מעולה". ל-screen reader: "דירוג גלים 4 מתוך 5, טוב".

**`QuickReactionBar`:** שני כפתורי toggle + כפתור "תגובה" שפותח את ה-composer ב-`ReplyThread`.
- "אני בא" (`coming`) ו"בדרך" (`on_the_way`). מצב נבחר מסומן בצורה (אייקון מלא + `aria-pressed`) ולא רק בצבע.
- לחיצה אחת = INSERT ל-`replies` עם `quick_reaction` ו-`text = null`.
- אפשר לבחור רק אחד מהשניים לכל דיווח. לחיצה על השני מחליפה (DELETE של הקודם שלי + INSERT חדש).
- לחיצה נוספת על הנבחר = ביטול (DELETE של התגובה שלי). זה מונע כפילויות בלי unique בצד DB.

**`ReplyThread`:** רמה אחת בלבד (spec §14). מכווץ כברירת מחדל: שורת סיכום. פתיחה מציגה עד 5 תגובות אחרונות + "הצג את כל התגובות", ו-composer (שדה טקסט עד 200 + כפתור "שלח").
- תגובה: אווטאר קטן, שם, `RelativeTime`, ואם יש `quick_reaction` מוצג תג "אני בא" / "בדרך", אחריו `text` אם יש. תגובת reaction בלבד מוצגת כתג בלבד.
- מחיקת תגובה שלי: ⋯ > "מחק" (ללא מודאל, עם undo toast).

**סינון (TopBar):**
- כפתור "סינון" פותח `FilterSheet` (bottom sheet) עם `BeachPicker` במצב סינון: אפשרות "כל החופים", אחריה קיבוץ לפי `beaches.region` (צפון / מרכז / דרום). בכל קבוצה: כל החוף (בחירה בקבוצה כולה = סינון אזור) ובתוכה חופים (`name_he` + `city`). חיפוש טקסט קצר מעל הרשימה.
- מצבי סינון: הכל · אזור (`region`) · עיר (`city`) · חוף (`beach_id`). בספק נדרש "חוף או עיר", לכן קבוצות העיר מופיעות כשיש יותר מחוף אחד בעיר (חיפה, תל אביב, אשקלון).
- הסינון נשמר ב-URL: `/?beach=7` / `/?city=חיפה` / `/?region=North`, כדי ש-back, refresh ושיתוף קישור יעבדו.
- כשמסונן לחוף יחיד: מתחת ל-TopBar מופיע `StripForecast`: שורה קומפקטית שמשתמשת ב-`ForecastSummary` (גובה, מחזור) עם קישור "לתחזית המלאה" ל-`/beach/[id]`. בכך דף החוף נגיש מהפיד גם בלי פריט ניווט ייעודי.
- "נקה סינון" דרך ה-chip (✕).

**מצבים:**
- **Loading ראשוני:** 3 שלדים של `ReportCard` (אווטאר עגול, 2 שורות, בלוק תמונה). TopBar ו-BottomNav מוצגים מיד.
- **Loading עמוד נוסף:** שלד אחד בתחתית. הטעינה מתחילה כ-400px לפני הסוף (20 דיווחים בעמוד, cursor לפי `created_at`).
- **Empty (אין דיווחים כלל):** `EmptyState`: איור קווי מינימלי של גל, "עדיין שקט בים. היו הראשונים לדווח", כפתור ראשי "דווחו עכשיו" > `/new`.
- **Empty בסינון:** "אין דיווחים מ{שם חוף} בימים האחרונים", כפתורים "נקו סינון" ו"דווחו מ{שם חוף}" > `/new?beach=<id>`.
- **Error:** `InlineBanner` בראש הרשימה: "לא הצלחנו לטעון את הפיד", כפתור "נסו שוב". אם כבר יש דיווחים בזיכרון, הם נשארים והבאנר מעליהם.
- **Error בעמוד נוסף:** שורה בתחתית "לא הצלחנו לטעון עוד. נסו שוב".
- **Offline:** `OfflineBanner` קבוע מתחת ל-TopBar: "אין חיבור. מציגים את מה שנטען עד עכשיו". הפיד שנטען נשאר. כפתורי תגובה ו-FAB נשארים פעילים אך שליחה תציג את מסר ה-offline (ראו §3). בחזרת החיבור: הבאנר נעלם, ה-realtime מתחבר מחדש ומשלים פערים (שאילתה לפי `created_at > האחרון שנראה`).
- **סוף הרשימה:** "זה הכל לעכשיו".
- **Success:** דיווח שלי שפורסם מופיע בראש הפיד (ראו Optimistic).
- **Optimistic:** ראו מטה.

**אינטראקציות ו-micro-interactions:**
- **Realtime insert (`reports`):**
  - אם המשתמש בראש הרשימה (scrollTop קרוב ל-0): הכרטיס החדש נכנס עם אנימציית החלקה קצרה מלמעלה ודוחף את היתר. אין קפיצת גלילה בלתי צפויה, כי המשתמש כבר בראש.
  - אם גלל למטה: **לא** מוסיפים לרשימה. מופיע `NewReportsPill` "3 דיווחים חדשים ↑" (מתעדכן במספר, `aria-live="polite"`). לחיצה: גלילה חלקה לראש + מיזוג הדיווחים. נעלמת גם כשהמשתמש גולל חזרה לראש.
  - בפיד מסונן נספרים רק דיווחים תואמים לסינון.
  - דיווח שלי לעולם לא נספר בפיל (הוא כבר נכנס אופטימית).
- **Realtime insert (`replies`):** מונה התגובות על הכרטיס מתעדכן בשקט (אנימציית "נעילה" קצרה על המספר). אם ה-`ReplyThread` פתוח, התגובה מתווספת בסופו בלי גלילה.
- **Realtime delete:** כרטיס שנמחק נעלם בקיפול קצר (אם לא נמצא מול העין). אם המשתמש פתח אותו: "הדיווח הזה נמחק".
- **חיבור Realtime נפל:** אינדיקטור קטן ב-TopBar ("מתחברים מחדש...") רק אחרי 5 שניות ניתוק, כדי לא להרעיש.
- **Pull-to-refresh:** ג׳סטה מקובלת בנייד לרענון ידני.
- **לחיצה על ReportCard (גוף):** פותחת/סוגרת טקסט מלא. שם משתמש > `/profile/[id]`. שם חוף > `/beach/[id]`.
- **Optimistic:** "אני בא"/"בדרך" מתעדכנים מיד (המונה גדל, הכפתור במצב נבחר). בכשל: חזרה למצב קודם + toast "לא הצלחנו לשלוח. נסו שוב". פרסום דיווח: ראו §2.3.
- **מחיקת דיווח שלי:** ⋯ > "מחק דיווח" > מודאל אישור (ראו §3.5). בזמן המחיקה הכרטיס מעומעם, בהצלחה נעלם עם toast.

### 2.3 New Report — `/new`

**מטרה:** לפרסם דיווח תוך ≤15 שניות. אחרי שהחוף נבחר: **≤3 לחיצות** (לחיצה על דירוג, כתיבה/בחירת טקסט מהיר, "פרסם"). תמונה אופציונלית ולא נספרת.

```
┌─────────────────────────────┐
│ ←  דיווח חדש                │  <- TopBar (כפתור חזרה בימין)
├─────────────────────────────┤
│ חוף                         │
│ ┌─────────────────────────┐ │
│ │ חוף הילטון · תל אביב  ▾ │ │  BeachPicker (ברירת מחדל מוגדרת)
│ └─────────────────────────┘ │
│                             │
│ איך הגלים?                  │
│  [1]  [2]  [3]  [4]  [5]    │  WaveRating (קלט, 5 כפתורים)
│  שטוח            מעולה      │
│                             │
│ מה קורה בחוף?               │
│ ┌─────────────────────────┐ │
│ │                         │ │  textarea
│ └─────────────────────────┘ │
│ (גלים נקיים) (עמוס) (ריק)   │  QuickTextChips (חדש, אופציונלי)
│                      0/500  │
│                             │
│ גובה גל (לא חובה)           │
│ (קרסול)(ברך)(מותן)(כתף)(ראש)│
│                             │
│ ┌──────────┐                │
│ │ + הוסיפו │  <- PhotoField │
│ │  תמונה   │                │
│ └──────────┘                │
├─────────────────────────────┤
│ ┌─────────────────────────┐ │
│ │        פרסמו            │ │  כפתור ראשי sticky מעל מקלדת
│ └─────────────────────────┘ │
└─────────────────────────────┘
```
ב-`/new` אין BottomNav ואין FAB (כדי לא להתחרות עם כפתור הפרסום).

**היררכיית רכיבים:** `NewReportPage` > `TopBar` (back) · `NewReportForm` > [`BeachPicker` (מצב בחירה), `WaveRating` (קלט), `Textarea`, `QuickTextChips` (חדש), `WaveHeightChips` (חדש, חלק מהטופס), `PhotoField` (חדש), `Button` (submit)].

**מיפוי נתונים (INSERT ל-`reports`):**

| שדה UI | עמודה | כללים |
|--------|--------|-------|
| BeachPicker | `beach_id` | חובה |
| WaveRating | `wave_rating` | אופציונלי (1–5). חייב להישלח כמספר |
| Textarea | `text` | חובה, 1–500 תווים (אחרי trim) |
| WaveHeightChips / שדה חופשי | `wave_height_estimate` | אופציונלי, טקסט |
| PhotoField | `image_url` | אופציונלי. URL ציבורי מ-`report-images` |
| (אוטומטי) | `user_id`, `created_at` | מהשרת |

**איך מגיעים ל-≤3 לחיצות:**
- **ברירת מחדל לחוף:** `?beach=<id>` אם הגענו מדף חוף/סינון, אחרת החוף האחרון שדווחתי ממנו (זיכרון מקומי), אחרת החוף המועדף הראשון, אחרת ריק (חובה לבחור, וזה לא נספר בחשבון כי החוף "כבר נבחר" לפי הדרישה).
- לחיצה 1: דירוג. לחיצה 2: צ'יפ טקסט מהיר ממלא את ה-textarea (אפשר להוסיף טקסט חופשי אחריו) או הקלדה. לחיצה 3: "פרסמו".
- **QuickTextChips:** "גלים נקיים", "עמוס בחוף", "ריק ושקט", "רוח חזקה", "גלים גדולים". רק מילוי טקסט, לא שדה חדש. (להאשר, ראו סוף המסמך.)
- מיקוד אוטומטי ב-textarea לא יופעל אם החוף חסר (כדי לא לפתוח מקלדת מעל ה-picker).

**BeachPicker (מצב בחירה):** bottom sheet עם חיפוש. המועדפים שלי בראש, אחר כך קיבוץ לפי `region`. כל שורה: `name_he`, `city`, תג רמת קושי (`difficulty`: "מתאים למתחילים" / "בינוני" / "למתקדמים", כטקסט).

**PhotoField:**
- לחיצה פותחת בורר מערכת (מצלמה/גלריה), `accept` תמונות (כולל heic).
- אחרי בחירה: תצוגה מקדימה (thumbnail) מיידית מהקובץ המקומי. ההעלאה מתחילה **מיד** ברקע (לא מחכים ללחיצה על "פרסמו"). דחיסה/הקטנה בצד לקוח (צלע ארוכה ~1600px) כדי להישאר מתחת ל-5MB ולחסוך נתונים.
- Progress: טבעת/פס על ה-thumbnail ואחוז. הערת מימוש: הספרייה הרגילה של Supabase Storage לא מדווחת progress אמיתי, אז או XHR/resumable או progress לא-מוגדר (indeterminate) עם טקסט "מעלים...". שני האפשרויות מקובלות ל-UX.
- הצלחה: סימון "הועלתה" (וי + טקסט, לא רק צבע). כפתור ✕ להסרה (מוחק את האובייקט שהועלה כדי לא להשאיר יתומים).
- כשל: מסגרת שגיאה + טקסט "ההעלאה נכשלה" + כפתורים "נסו שוב" ו"הסירו".
- קובץ גדול/לא נתמך: "התמונה לא מתאימה. אפשר JPG, PNG או WEBP עד 5MB".
- אם המשתמש לוחץ "פרסמו" בזמן העלאה: הכפתור במצב "מעלים תמונה..." (disabled) ומתפרסם אוטומטית עם סיום, או שאפשר "פרסמו בלי תמונה".

**מצבים:**
- **Loading:** טעינת רשימת חופים: שלד בתוך ה-picker. (הרשימה קטנה, 12, ויכולה להיות סטטית מהשרת.)
- **Validation (בעת blur + בעת submit):** חוף חסר: "בחרו חוף". טקסט ריק: "ספרו מה קורה בחוף". טקסט מעל 500: מונה באדום-מצב (אייקון + טקסט, לא צבע בלבד) וחוסם. המונה "0/500" מוצג מ-400 ומעלה, או תמיד אם יש מקום.
- **Error (שרת):** `InlineBanner` מעל הכפתור: "הפרסום נכשל. הטקסט והתמונה נשמרו, נסו שוב". הטופס לא מתנקה.
- **Offline:** הכפתור disabled עם "אין קליטה. נסו שוב כשיהיה חיבור". **טיוטה נשמרת** (localStorage) כולל חוף, דירוג וטקסט, ומשוחזרת בכניסה חוזרת. (הקליטה בחוף לא תמיד טובה. אין תור שליחה אוטומטי ב-v1, ראו Future.)
- **Success:** חזרה מיידית ל-`/` (או ל-`/beach/[id]` אם הגענו משם) עם toast "פורסם!". 
- **Optimistic update:** מיד אחרי "פרסמו" עוברים לפיד והכרטיס מופיע בראש עם מצב "שולח..." (מעומעם + אייקון שעון + טקסט "שולח..."). בהצלחה (תגובת Server Action / realtime echo) מתחלף לכרטיס רגיל בלי הבהוב (מזהים לפי client id זמני). בכישלון: הכרטיס נשאר עם "לא נשלח" וכפתורים "נסו שוב" / "מחקו", והטיוטה לא אובדת. אם יש תמונה שעדיין מועלית, הפרסום ממתין להעלאה ואז נשלח.
- **יציאה עם שינויים:** back/סגירה כשיש טקסט: מודאל "לשמור כטיוטה?" עם "שמרו" / "זרקו" / "המשיכו לערוך".
- **נגישות מקלדת:** כפתור "פרסמו" sticky מעל המקלדת (visual viewport) כדי שלא יוסתר.

**היררכיית רכיבים:** `BeachPage` > `TopBar` (back, `FavoriteToggle` חדש) · `ForecastSummary` · `WaveChart` · `ReportList` (מסונן ל-`beach_id`) > `ReportCard` · `FAB` · `BottomNav` · `PushOptInSheet` (חדש, ראו §4.5).

**מיפוי נתונים:**

| אלמנט | מקור |
|-------|------|
| שם, עיר, אזור, קושי, תיאור | `beaches.name_he` (+`name_en` כמשנה), `city`, `region`, `difficulty`, `description` |
| כוכב מועדף | קיום שורה ב-`user_favorites` (user_id + beach_id) |
| ForecastSummary / WaveChart | `/api/forecast/[beachId]` (Open-Meteo: `wave_height`, `wave_period`, `wave_direction` לפי שעה, `timezone=Asia/Jerusalem`) |
| דיווחים | `reports` לפי `beach_id`, כמו הפיד |

**ForecastSummary:** גובה גל נוכחי (מ׳), מחזור (שניות), כיוון (חץ מסתובב **ובנוסף** טקסט כיוון, לא חץ בלבד). שורה "עודכן לפני X דקות" (המטמון 30 דקות).
**WaveChart:** גרף קו/שטח של `wave_height` ל-24 שעות קדימה (ניתן להחליף ל-48 עם מתג "24 ש׳ / 48 ש׳"), ציר זמן בשעות, סימון "עכשיו". לחיצה/גרירה מציגה tooltip עם שעה + גובה + מחזור. לקוראי מסך: טבלה נסתרת חזותית עם אותם נתונים או סיכום טקסטואלי ("שיא 1.2 מ׳ ב-15:00").

**מצבים:**
- **Loading:** שלד לבלוק התחזית (מספרים + גרף) ושלדי כרטיסים. התחזית והדיווחים נטענים במקביל ואינם חוסמים זה את זה.
- **תחזית נכשלה:** בלוק עם "התחזית לא זמינה כרגע" + "נסו שוב". הדיווחים נשארים.
- **תחזית ישנה (offline):** מציגים מהמטמון האחרון עם "נתונים מ-לפני X". 
- **Empty דיווחים:** "אף אחד לא דיווח מכאן לאחרונה", כפתור "דווחו מ{חוף}".
- **חוף לא קיים:** מסך Not Found: "לא מצאנו את החוף הזה", כפתור "חזרה לפיד".
- **Offline:** כמו פיד. כוכב מועדף disabled.

**אינטראקציות:**
- **כוכב מועדף:** לחיצה = optimistic toggle (`toggleFavoriteBeach`) + toast "הוספנו ל{חוף} למועדפים" / "הוסר מהמועדפים". בכשל: חזרה לקודם + "לא הצלחנו לשמור. נסו שוב".
- בהוספה **ראשונה** למועדפים (ואם אין עדיין התראות פעילות במכשיר) נפתח `PushOptInSheet` (ראו זרימה 4.5). לא נפתח שוב אם סורב באותה session.
- FAB מוביל ל-`/new?beach=<id>`.

**מיפוי נתונים:**

- **יציאה עם שינויים שלא נשמרו:** מודאל "יש שינויים שלא נשמרו" (שמרו / זרקו).
- **מתג התראות (כבוי > דולק):** מפעיל את זרימת 4.5 (בקשת הרשאה בהקשר). 
  - הרשאה `denied` בדפדפן: המתג disabled + הסבר: "ההתראות חסומות בדפדפן. אפשר לשנות בהגדרות האתר ואז לחזור".
  - דפדפן לא תומך: "הדפדפן הזה לא תומך בהתראות".
  - iOS שלא הותקן למסך הבית: במקום מתג — `InstallHint` (ראו 4.5).
  - דולק > כבוי: מוחק את המנוי של המכשיר (`push_subscriptions`), בלי מודאל, toast "כיביתם התראות במכשיר הזה". ההתראות הן **per-device** והדבר מוסבר בשורת עזר.
  - אם אין חופים מועדפים והמתג דולק: הערה "אין עדיין חופים מועדפים, אז לא תקבלו התראות. הוסיפו חוף".
- **מועדפים:** "הסר" = optimistic + undo toast (5 שניות). "הוסיפו חוף" פותח `BeachPicker`.
- **התנתקות:** מודאל אישור קצר: "להתנתק?" [התנתקו] [ביטול]. לאחר מכן `/login`.
- **Loading:** שלד לטופס ולרשימת המועדפים.
- **Offline:** כל השמירות disabled עם הערה "אין חיבור".

### 2.7 Empty / Error / System states

מסך 7 הוא ספריית מצבים משותפת, מיוצגת ברכיב `EmptyState` (איור קווי מינימלי + כותרת + שורת הסבר + CTA אחד). כל מצב כבר מופיע בהקשר שלו למעלה; כאן הטבלה המרוכזת לעיצוב:

| מצב | איפה | כותרת | הסבר | CTA |
|-----|------|-------|------|-----|
| פיד ריק | `/` | עדיין שקט בים | היו הראשונים לספר מה קורה בחוף | דווחו עכשיו |
| סינון בלי תוצאות | `/?beach=` | אין דיווחים מ{חוף} | אולי עוד לא הגיעו לשם היום | נקו סינון / דווחו מכאן |

## 3. מצבים משותפים וכללי אינטראקציה

### 3.1 שלדי טעינה (Skeleton)
שלד שחוזר על צורת התוכן: `ReportCardSkeleton` (אווטאר, 2 שורות, בלוק תמונה), `ForecastSkeleton`, `ProfileHeaderSkeleton`. אנימציית shimmer עדינה, מכבדת `prefers-reduced-motion` (אז סטטי). `aria-busy="true"` על הרשימה.

### 3.2 Optimistic vs. wait-for-server

| פעולה | אסטרטגיה |
|-------|----------|
| "אני בא" / "בדרך" | Optimistic. rollback + toast בכשל |
| ביטול reaction שלי | Optimistic |
| תגובת טקסט | Optimistic (מופיעה עם "שולח..."), בכשל "לא נשלח. נסו שוב" באותה שורה |
| פרסום דיווח | Optimistic (כרטיס "שולח...") |
| מועדף (כוכב) | Optimistic |
| מחיקת דיווח/תגובה | Wait-for-server עם עמעום, ואז הסרה (לא מוחקים מהמסך לפני שהצליח) |
| שמירת פרופיל | Wait-for-server (כפתור עם spinner "שומרים...") |
| מתג התראות | Wait-for-server (תלוי בהרשאת דפדפן) |

### 3.3 ולידציה
בדיקה ב-**blur** וגם ב-**submit**. שגיאה מוצגת מתחת לשדה עם אייקון + טקסט, מקושרת ב-`aria-describedby`, ו-`aria-live="polite"`. הפוקוס עובר לשדה השגוי הראשון ב-submit כושל.

### 3.4 Toasts
קצרים, תחתית המסך מעל ה-BottomNav, נעלמים אחרי 4 שניות, עם כפתור פעולה אם רלוונטי ("בטל"). `role="status"`.

### 3.5 מודאלי אישור (פעולות הרסניות בלבד)

| פעולה | כותרת | כפתורים |
|-------|-------|---------|
| מחיקת דיווח | למחוק את הדיווח? | [מחקו] (מסוכן) / [ביטול] |
| יציאה מ-/new עם טקסט | לשמור כטיוטה? | [שמרו] / [זרקו] / [המשיכו לערוך] |
| התנתקות | להתנתק? | [התנתקו] / [ביטול] |
| יציאה מהגדרות עם שינויים | יש שינויים שלא נשמרו | [שמרו] / [זרקו] |

אלה לא דורשים מודאל: מחיקת תגובה שלי (undo toast), הסרת מועדף (undo toast), ביטול reaction.
טקסט המחיקה: "הדיווח וכל התגובות אליו יימחקו. אי אפשר לשחזר."

### 3.6 Offline
`OfflineBanner` גלובלי ב-`(app)/layout` לפי `navigator.onLine` + כשל fetch. כל פעולת כתיבה מסרבת בעדינות ("אין חיבור, נסו שוב") ולא נעלמת בשקט. תוכן שכבר נטען נשאר. אין תור offline ב-v1.

## 4. זרימות ליבה

### 4.1 כניסה ראשונה > פיד

```
משתמש פותח URL
   |
   v
[/ ] לא מחובר? --כן--> /login?next=/
   |                      |
   |                      v  "המשך עם Google"
   |                  Google consent
   |                      |
   |                      v
   |                  /callback  (שרת: session; טריגר יוצר profiles)
   |                      |
   |<---------------------+  redirect ל-next (ברירת מחדל /)
   v
[/ Feed]
   |-- יש דיווחים: ReportList
   '-- אין דיווחים: EmptyState "עדיין שקט בים" + [דווחו עכשיו]
```
- אין onboarding בנפרד. שם ואווטאר נלקחים מ-Google. הפרופיל ניתן להשלמה ב-`/settings` בהמשך (לא חוסם).
- נקודות כשל: ביטול ב-Google (חזרה ל-`/login` עם שגיאה), callback נכשל (`/login?error=`), דפדפן פנימי (הנחיה לפתוח בדפדפן).

### 4.2 פרסום דיווח (יעד: ≤15 שניות, ≤3 לחיצות אחרי בחירת חוף)

```
[/ Feed] --FAB (+)--> [/new]  (חוף ממולא מראש אם ידוע)
   |
   | 1. בחירת חוף (אם לא מולא)         <- לא נספר
   | 2. לחיצה: דירוג 1-5                 (לחיצה 1)
   | 3. לחיצה: צ'יפ טקסט / הקלדה         (לחיצה 2)
   |    [אופציונלי: תמונה, גובה גל]      <- לא נספר
   | 4. לחיצה: "פרסמו"                   (לחיצה 3)
   v
Server Action createReport
   |-- optimistic: חזרה ל-/ עם כרטיס "שולח..."
   |-- הצלחה: כרטיס רגיל + toast "פורסם!" ; Realtime מעדכן אחרים; push לחופים מועדפים
   '-- כישלון: כרטיס "לא נשלח" + [נסו שוב] [מחקו] ; טיוטה נשמרת
```
- בלי קליטה: "פרסמו" disabled + הסבר, טיוטה נשמרת.

### 4.3 תגובה "אני בא" בלחיצה אחת

```
ReportCard (בפיד / בדף חוף)
   |
   |-- לחיצה על [אני בא]
   v
optimistic: כפתור במצב נבחר, מונה +1  (מיידי, ללא מודאל וללא ניווט)
   |
   v
INSERT replies { report_id, quick_reaction:'coming', text:null }
   |-- הצלחה: אין שינוי חזותי נוסף; המשתמש מופיע ברשימת התגובות
   '-- כשל: rollback + toast "לא הצלחנו לשלוח. נסו שוב"

לחיצה נוספת על [אני בא] = ביטול (DELETE של התגובה שלי)
לחיצה על [בדרך] כשיש לי "אני בא" = החלפה
```
- בעל הדיווח לא צריך כפתורי reaction על הדיווח של עצמו (מוסתרים). הוא יכול להגיב בטקסט.

### 4.4 סינון לפי חוף / עיר

```
[/ Feed] --TopBar "סינון"--> FilterSheet
   |
   | רשימה: כל החופים | צפון | מרכז | דרום
   |        ועיר (חיפה/תל אביב/אשקלון) | חוף בודד
   | חיפוש טקסט
   v
בחירה --> URL /?beach=ID  (או ?city= / ?region=)
   |
   v
ReportList מסונן + chip בראש "חוף הילטון ✕"
   '-- אם חוף יחיד: StripForecast + קישור ל-/beach/[id]
נקה: ✕ על ה-chip --> /
```
- Realtime: רק דיווחים תואמים נספרים ב-`NewReportsPill`.
- סינון נשמר בחזרה מ-`/beach/[id]` ומ-`/profile/[id]` (דרך history).

### 4.5 חוף מועדף + הפעלת Push

ההרשאה מבוקשת **בהקשר**, לעולם לא בטעינת האפליקציה, ותמיד אחרי לחיצה מפורשת של המשתמש.

```
[/beach/ID] --לחיצה על ☆--> optimistic: ★ + toast "הוספנו למועדפים"
   |
   | זו המועדפת הראשונה / אין מנוי במכשיר זה / לא סורב ב-session?
   v
PushOptInSheet:
  "רוצים שנעדכן אתכם כשיש דיווח חדש ב{חוף}?"
  [כן, עדכנו אותי]   [לא עכשיו]
   |
   +-- "לא עכשיו": נסגר. אפשר להפעיל מאוחר יותר ב-/settings. לא נשאל שוב באותה session.
   |
   +-- "כן":
         |
         v
   תנאי פלטפורמה?
     iOS ובדפדפן רגיל (לא standalone)?
        --> InstallHint (במקום בקשת הרשאה):
            "באייפון צריך קודם להוסיף את surFriends למסך הבית.
             לחצו על 'שיתוף' ואז 'הוסף למסך הבית', ופתחו משם."
            [הבנתי]   (ההרשאה לא מבוקשת בשלב זה)
     iOS standalone / Android / Desktop:
        --> Notification.requestPermission()
              |-- granted: subscribeToPush -> INSERT push_subscriptions
              |            toast "נעדכן אתכם על דיווחים חדשים ב{חוף}"
              |-- denied:  sheet נסגר, הערה "ההתראות חסומות. אפשר לשנות בהגדרות הדפדפן"
              '-- dismissed: כמו "לא עכשיו"
```
- אותה זרימה מופעלת מהמתג ב-`/settings` (שם המשתמש כבר ביקש במפורש).
- קבלת ההתראה: כותרת "דיווח חדש ב{חוף}", גוף: `{שם}: {טקסט מקוצר}`. לחיצה פותחת `/beach/[id]`. המדווח עצמו לא מקבל התראה על דיווח שלו.
- התראות הן per-device. אותו משתמש יכול להפעיל בכמה מכשירים.

## 7. נגישות

- **Touch targets:** כל אלמנט אינטראקטיבי לפחות 44x44px (כולל "אני בא", כוכב, ✕ ב-chip, תווי דירוג, פריטי BottomNav, כפתור הסרה). רווח מינימלי בין יעדים סמוכים כדי למנוע לחיצות שגויות (ברשת כפפות/ידיים רטובות בחוף).
- **עברית ו-RTL:** `lang="he" dir="rtl"` ב-root. כל תווית, placeholder, aria-label והודעת שגיאה בעברית. שמות חופים באנגלית (`name_en`) רק כמשנה. מספרים וזמנים מוצגים בכיוון נכון (bidi isolation על שמות לועזיים).
- **דירוג גלים 1–5 לעולם לא בצבע בלבד:** מספר + צורה (סימנים מלאים/ריקים) + תווית מילולית (שטוח/חלש/סביר/טוב/מעולה). ב-screen reader: "דירוג גלים 4 מתוך 5, טוב". קלט הדירוג הוא `radiogroup` עם 5 כפתורים, `aria-checked`, ותמיכה בחצים.
- **מצבים לא בצבע בלבד:** נבחר/לא נבחר (`aria-pressed`), שגיאה (אייקון + טקסט), "שולח..."/"לא נשלח" (טקסט + אייקון), כיוון גל (חץ + טקסט), קושי חוף (טקסט).
- **ניגודיות:** קריא בשמש. יעד AA לפחות, ובטקסטים עיקריים AAA כשאפשר. (קביעת הערכים אצל ה-visual-designer.)
- **תוויות:** לכל שדה `label` גלוי. כפתורי אייקון (כוכב, סינון, ✕, ⋯) עם `aria-label` בעברית ("הוספה למועדפים", "סינון דיווחים").
- **Live regions:** שגיאות ולידציה, `NewReportsPill`, toasts (`role="status"`), מצב העלאת תמונה, ו"אין חיבור" מוכרזים ב-`aria-live="polite"`. שגיאות חוסמות (כשל פרסום) ב-`role="alert"`.
- **פוקוס:** סדר הגיוני (TopBar > תוכן > FAB > BottomNav). Bottom sheets ומודאלים לוכדים פוקוס, נסגרים ב-Escape, ומחזירים פוקוס לכפתור שפתח אותם. אחרי submit כושל הפוקוס עובר לשדה השגוי הראשון. טבעת פוקוס גלויה.
- **מקלדת:** כל הזרימות פועלות במקלדת. חיצים בדירוג ובבחירות.
- **תמונות:** `alt` = טקסט הדיווח המקוצר או "תמונה מ{חוף}". אווטארים דקורטיביים (`alt=""`) כשהשם כתוב לידם.
- **תנועה:** כיבוד `prefers-reduced-motion` (בלי אנימציית כניסת כרטיס/shimmer/גלילה חלקה).
- **זמנים:** `<time datetime>` עם `aria-label` של הזמן המלא.
- **Zoom:** לא חוסמים pinch-zoom. הטקסט מתאים ל-200% בלי אובדן תוכן.
- **Safe areas:** BottomNav ו-FAB מכבדים safe-area (iOS) וגובה מקלדת.

## 9. שאלות פתוחות / החלטות לאישור

1. `QuickTextChips` ו-`WaveHeightChips` ב-/new: עזרים כדי לעמוד ב-≤3 לחיצות. אם לא רוצים, מורידים בלי השפעה על הסכמה.
2. `wave_height_estimate` קיים בסכמה אבל לא ברשימת השדות בבריף. הוצג כאופציונלי בלבד.
3. BottomNav עם 3 פריטים (פיד / פרופיל / הגדרות), ו"דיווח חדש" כ-FAB בלבד. אין route לרשימת חופים.
4. מחיקת "אני בא" בלחיצה חוזרת (toggle) מסתמכת על DELETE של תגובה שלי (מותר ב-RLS). אין unique ב-DB, אז זה אכיפת-UI. מומלץ (אופציונלי) ל-backend להוסיף אינדקס ייחודי.
5. אין העלאת אווטאר (אין bucket מתאים). האווטאר הוא של Google.
6. התראות per-device; חופים מועדפים per-user.
